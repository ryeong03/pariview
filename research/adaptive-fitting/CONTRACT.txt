PariView 적응형 선호 피팅 — 구현·평가 계약 v1
2026-11-04 · 연구 담당 / 엔진 02ee / UI root

1. 추정 대상과 비교 예산
밝기 [45,100], 대비 [65,110], 음량 [0,70]의 연속 선호 설정을 탐색한다
각 축의 범위로 정규화한 값은 0–1이다
압축과 쉬운 자막은 boolean이므로 이 추정기에 넣지 않고 결과 화면에서 직접 선택한다
빠른 탐색 5회 + 사용자가 요청하면 5회씩 추가, 총 20회 상한
5회는 확정된 비교 응답의 예산이며 수렴 보장 횟수가 아니다
질문 발급·확정 응답·유효 A/B 수는 별도로 기록한다 (중단·undo로 서로 달라질 수 있음)
equal / unsure / skip도 한 번의 제시를 사용하므로 예산에 포함한다

2. 모델
각 축별 θ∈{0,.01,...,1}의 균등 prior, 101칸
시작 프로필 값은 사용자가 아직 답하지 않은 축의 출력값으로 유지한다
프로필이나 진단명을 θ의 정답 또는 정보성 prior로 사용하지 않는다
u(x;θ)=−(x−θ)^2
P(A|θ)=λ/2+(1−λ)·sigmoid((u(A;θ)−u(B;θ))/τ)
기본 λ=.10, τ=.08, 독립 3축, 단봉형 선호라는 팀 모델 가정
λ와 τ는 임상값·문헌 권고값이 아니라 버전 고정된 모델 파라미터다
A/B 확정 시 해당 축 posterior ∝ prior×선택 likelihood, 합이 1이 되도록 정규화
추정 설정은 posterior 중앙값을 실제 범위로 환산·정수 반올림한다
무응답 축은 시작 설정을 유지한다

3. 다음 비교 선택
후보 축값은 정규화 0,.05,...,1의 21칸을 실제 단위 정수로 반올림한 뒤 중복 제거
실제 제시값을 다시 정규화하여 likelihood를 계산한다 (반올림 전 값으로 계산하지 않음)
후보 A<B, 정규화 간격 .10–.50, 실제 값 간격 최소 2
처음 세 번은 아직 제시하지 않은 축을 우선하여 각 축을 한 번씩 제시한다
firstAxis가 있으면 첫 축만 지정하고, 남은 미제시 축은 정보이득으로 고른다
이후 모든 허용 축·쌍 중 기대 정보이득(IG)이 최대인 쌍을 고른다
IG=H(Σθ pθ·Lθ)−Σθ pθ·H(Lθ), H는 이진 엔트로피(bits), Lθ=P(A|θ)
동률은 brightness→contrast→volume, 다음은 낮은 A→낮은 B 순으로 결정한다
이미 제시한 축·수치 쌍은 반복하지 않는다 (undo는 예외)
skip한 축은 바로 다음 한 질문에서 유예한다; 다른 후보가 없으면 유예 해제
좌우 A/B 배치만 seed 기반으로 바꾼다; 정준 후보쌍과 실제 배치를 모두 기록한다
음량은 작은 후보부터 사용자가 재생하며, 재생 자체는 엔진 밖의 UI가 제어한다

4. 무차이·모름·건너뛰기
equal: 비슷하게 느껴짐, unsure: 판단 보류, skip: 해당 비교를 진행하지 않음
세 응답은 각각 기록하지만 posterior와 추정값을 갱신하지 않는다
equal을 구간 중앙점의 정답으로 바꾸거나 불확실성을 인위적으로 축소하지 않는다
AB 유효응답 수와 전체 제시 수를 따로 표시한다

5. 종료 및 불확실성
기본 종료 사유: budget / user / no_candidates
정밀도 조건: 모든 축에 유효 A/B 응답 최소 2회 AND 각 축 중앙 80% posterior 구간 폭≤전체 범위 .15
조건 충족 시 precision 종료 가능; 의미는 현재 모델 내부의 구간 축소다
이 조건은 기본 5회 예산에서 성립할 수 없으며, 예산 종료를 정밀도 충족으로 표시하지 않는다
extend(5)는 예산에 5를 더하고 상한 20 적용; 사용자 요청 후에만 재개한다
무응답만 있는 세션은 시작 설정 그대로, posterior 균등 그대로 반환한다

6. 순수 JS API 계약
createAdaptiveFit({settings,budget:5,seed,context,firstAxis,policy:'adaptive'})
peek(): 현재 question 순수 조회; 여러 번 조회해도 ID·후보·배치·posterior 불변
answer(questionId,'a'|'b'|'equal'|'unsure'|'skip'): 다음 버튼에서 한 번만 확정; 중복·과거 ID 거부
undo(): 마지막 확정 응답을 제거하고 해당 질문의 같은 후보쌍·배치 복원
extend(5), stop(), result(), snapshot()
question={id,axis,a,b,queryIndex,placement,expectedInformationGain,...}
result={settings,answered,budget,stopReason,counts,uncertainty,...}
snapshot에는 엔진 버전, 범위, grid, λ,τ, prior, seed, context, 시작값, 후보 실제값,
좌우 배치, 결과, 질문별 posterior·추정값·불확실성, 종료 사유를 보존한다
issued / discarded 기록으로 미응답 중단과 undo를 보존하며, 미확정 응답으로 선호를 갱신하지 않는다
context에는 clipId / segment / playbackRate / 고정 옵션이 들어갈 수 있다
개인 신원·진단 원문을 context에 기록하지 않는다

7. 평가 계약 — 주 비교
동일한 5회·3개 연속 축·범위·prior·likelihood·추정기를 사용한다
주 기준선은 응답과 무관하게 미리 정한 후보쌍을 제시하는 fixed 정책이다
fixed 순서: brightness,contrast,volume 반복
각 축의 제시 차수별 중심은 .50,.25,.75,.125,.375,.625,.875,... 순서
간격 .50; 범위를 벗어나면 구간 전체를 평행이동해 범위 안에 유지
엔진의 후보 격자에서 중심·간격이 가장 가까운 쌍을 고르고, 동률은 정준 순서
선택에 따라 다음 쌍은 바뀌지 않지만 posterior 업데이트와 출력 추정기는 adaptive와 동일
fixed는 검증용 policy이며 제품 기본은 adaptive
fixed 정책에는 응답 기반 skip 축 유예와 firstAxis를 적용하지 않는다
격자 쌍의 근접도는 |중심 차이|+|간격 차이|로 정하고 동률은 정준 순서를 따른다
현재 고정 5회(숫자 3회+boolean 2회) 결과는 별도 참고선으로만 사용한다
현행 수치쌍 65/90,78/105,22/45에서 고른 값을 직접 쓰는 방식과
적응형 5숫자 비교는 정보량·추정기가 다르므로 이것만으로 우월성을 주장하지 않는다

8. 시뮬레이션 계약 — 실제 이용자 데이터와 분리
기본 seed 20261104, 각 조건당 합성 선호점 500개, θ 각 축 독립 Uniform(0,1)
정답 θ와 응답 생성 규칙은 시뮬레이션에만 존재한다
조건: deterministic / matched(τ=.08,λ=.10) / noisy(τ=.16,λ=.20)
      nonresponse(matched + equal10%/unsure10%/skip5%)
      asymmetric(u의 x<θ 쪽 계수1.5, x≥θ 쪽 .6; τ=.08,λ=.10)
조건별 고정 seed와 동일 합성 선호점 사용, 응답용 난수와 배치용 난수는 분리
질문 0~5회의 정규화 MAE = mean_axis |추정값−θ| / 축 범위
평균 곡선과 합성 사례 bootstrap 95% 구간, 5회 오차의 paired 차이를 보고한다
보조지표: 5회 NMAE≤.10 비율, posterior 80% 구간의 θ 포함률, 실제 제시·유효응답 수
유리한 조건만 뽑지 않고 모든 조건과 seed·원시 합성 로그를 보존한다
초기 설정은 동일한 everyday 값 brightness85/contrast90/volume35, boolean은 평가 제외
동일 5회 결과로 20회·실사용자·다른 영상의 성능을 추정하지 않는다

9. 당사자 실험 연결
기존 완료 여부 사용자 확인과 별개인 새 알고리즘 비교용 서식이다
실제 응답 기록이 없으므로 현재 참여자 곡선·SUS 점수·편안함 변화량은 생성하지 않는다
같은 클립·구간·속도·기기·재생 음량, 자동 장면 변경/밝기 보정 등 조건 고정
adaptive와 fixed를 같은 예산으로 순서 교차, 추정 중간값은 모델 불확실성으로 표시
실험 후 독립적으로 반복 조절한 선호 범위와 결과 설정의 거리·최종 선택·부담·소요시간을 측정
실제 사람의 단일 '참값'을 임의로 정의하지 않고 반복 참조 설정의 변동도 함께 기록한다
