# AI 페르소나 시뮬레이션 보고서

> **AI 페르소나 시뮬레이션이에요 실제 사용자 평가가 아니에요**
> 페르소나의 원하는 설정값은 연구팀이 정한 가정이에요 이 결과는 "피팅 흐름이 서로 다른 목표값에 얼마나 가까이 데려가는가"를 확인한 것이지, 사람들이 실제로 이렇게 다르다는 근거가 아니에요

## 무엇을 했나

- 대상: PariView의 다섯 대상층(고령층, 자폐, ADHD, 아동, 일반)에 청각 저하를 더해 층별로 10명을 구성했어요 ([personas.json](personas.json))
- 근거: 나이, 기기, 시청 환경은 공식 통계를 바탕으로 골랐어요
  - 2025년 65세 이상 인구 20.3% (통계청 2025 고령자 통계)
  - 2024년 등록장애인 263만 명, 인구의 5.1% (보건복지부 현황 보도)
  - 2024년 ADHD 진료 인원 26만 명, 10대 35.6%·20대 25.3% (국민건강보험공단 자료 보도)
  - 2024년 OTT 이용률 79.2%, OTT 이용 시 스마트폰 91.2% (방송통신위원회 방송매체 이용행태조사)
- 방법: [simulate.py](simulate.py)가 실제 PariView 화면(`web/dist`)을 자동으로 조작해요
  - 페르소나가 고를 시작 모드를 누르고, A/B 비교 5단계마다 원하는 값에 더 가까운 쪽을 골라요
  - 두 선택지가 거의 같게 가까우면 "비슷해요"를 골라요
  - 마지막에 "이 설정으로 시청하기"를 누르고 저장된 설정을 읽어요
- 지표: 밝기·대비·소리 크기의 차이를 각 설정 범위로 나눈 정규화 오차(0이면 원하는 값과 같음), 켜기/끄기 항목(음량 변화 완화, 쉬운 자막) 일치율, 클릭 수

## 시뮬레이션이 찾아낸 문제

**고정된 두 값 중 하나만 고르는 구조라서 끝값에 가까운 사람은 원하는 값에 못 닿아요**

- 소리 크기 선택지가 22와 45뿐이라 큰 소리가 필요한 P09(60)와 P01(55)은 45에서 멈춰요 P09는 오차가 0.174에서 0.158로 거의 줄지 않았어요
- 대비 선택지가 78과 105뿐이라 중간값을 원하는 P07(88)은 78로, P06(95)은 105로 밀려요
- 개선안: 첫 선택 뒤에 고른 쪽 가까이에서 한 번 더 비교하는 2단계 비교(예: 45를 고르면 45와 60 비교)를 넣으면 클릭 2~3회를 더 써서 끝값까지 닿을 수 있어요

## 한계

- 원하는 값은 연구팀의 가정이라, 오차 감소는 "흐름이 목표에 다가갈 수 있다"는 뜻일 뿐 실제 사용자의 만족이나 편안함을 뜻하지 않아요
- 페르소나는 망설임, 실수, 피로 없이 항상 더 가까운 쪽을 골라요 실제 사람은 더 많이 흔들려요
- 클릭 수는 셌지만 걸린 시간은 사람이 아니라서 의미가 없어 기록하지 않았어요
- 사용성 점수(SUS)는 사람이 직접 답해야 하는 설문이라 AI로 대신 만들지 않았어요 [sus-form.md](sus-form.md)로 실제 사용자에게 받아야 해요

## 다시 실행하기

```bash
python3 web/serve.py   # 또는 web/dist를 127.0.0.1:4178로 띄운 상태에서
python3 analysis/simulation/simulate.py http://127.0.0.1:4178/ analysis/simulation/results.json
```

`app.js`의 A/B 값이 바뀌면 시뮬레이터가 먼저 멈추고 알려줘요
