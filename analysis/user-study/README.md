# 실제 사용자 피팅 실험 (5~10명, 1명당 12분)

기존 대안 설계 문서예요 아래 절차는 직접 찾은 선호값과 피팅값의 수치 차이를 살피는 별도 방법이에요 실제 응답이나 결과는 포함하지 않아요
핵심은 **참가자가 먼저 직접 찾은 선호값**을 기준으로 잡는 거예요 그래야 "왜 팀이 정한 값이 정답이냐"는 질문이 안 나와요

## 준비

- 공개 데모 https://pariview-production.up.railway.app/ 를 새 시크릿 창에서 열기 (저장값이 비어 있어야 해요)
- 기록은 [results.csv](results.csv)에 한 줄씩 (열 설명은 아래)
- 참가자는 번호(U01…)로만 적고, 진단명은 묻지 않아요 "소리·빛에 민감한 편인지"만 본인이 고르게 해요

## 순서

1. **기본값으로 보기** 장면 1을 기본값(밝기 85 · 대비 90 · 소리 35)으로 20초 보고 "지금 편안한가요?"를 1~5로 받아요 → `comfort_before`
2. **직접 찾기** 세부 설정을 펼쳐 밝기·대비·소리 슬라이더를 마음대로 움직여 "제일 편한 값"을 찾게 해요 시간 제한 없음 값을 적어요 → `pref_*`
3. **기본값으로 초기화**하고 "나의 감각 피팅 시작"을 눌러요 시작 모드 선택부터 "이 설정으로 시청하기"까지 걸린 시간을 재요 → `fit_seconds`, 결과값 → `fit_*`
4. **피팅 결과로 보기** 같은 장면을 20초 보고 "지금 편안한가요?"를 1~5로 받아요 → `comfort_after`
5. 한 문장 "제일 헷갈린 화면은?" → `note` (선택) SUS 10문항은 [../simulation/sus-form.md](../simulation/sus-form.md)

## 열 설명

| 열 | 뜻 |
|---|---|
| id | U01, U02 … |
| group | sensitive(소리·빛에 민감한 편) / typical(그렇지 않음) 본인 선택 |
| age_band | 10대 / 20대 / 30대 / 40대 / 50대 이상 |
| device | 노트북 / 태블릿 / 스마트폰 |
| pref_brightness, pref_contrast, pref_volume | 2단계에서 직접 찾은 값 |
| fit_brightness, fit_contrast, fit_volume | 3단계 피팅 결과값 |
| fit_seconds | 피팅에 걸린 시간(초) |
| comfort_before, comfort_after | 1~5 (5 = 매우 편안) |
| sus | 0~100 (선택, 비우면 집계에서 제외) |

## 집계

```bash
python3 analysis/user-study/user_study.py analysis/user-study/results.csv
```

포스터에 바로 넣을 수 있는 문장이 나와요 예: "실제 사용자 8명 · 직접 찾은 선호값과의 오차 0.21 → 0.06 · 8명 중 7명이 피팅 후 더 편안하다고 답함 · 평균 2분 10초"

## 표기 원칙

- n과 대상을 앞에 써요: "실제 사용자 8명(소리·빛에 민감한 편 5명 · 그렇지 않은 3명, 지인 모집)"
- 오차 감소는 알고리즘 지표, 편안함 점수는 사용자 지표예요 둘 다 써요
- 5~10명은 작은 표본이라 "사전 사용성 점검"이라고 부르고 일반화하지 않아요
